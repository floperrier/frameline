# A Name is asked for in the listing, and nowhere else

Every entry in the Catalogue is signed, so an Author needs a Name before a Story
of theirs can be Listed — ADR 0023 already says listing is the moment that falls
due. What was decided here is where the product asks. Two answers were on offer:
a step between signing in and the bench, or a settings page an Author is sent to.
Both were refused. A form between a new account and their first Story costs more
than it collects — the Sample is what the first screen is for — and a settings
page for one field is a room built to hold a single chair.

So the Name is asked for in the listing itself: the first time an Author lists a
Story, in the panel the button lives in, and only if it is empty. Answering it
lists the Story in the same gesture, because writing the Name was never the thing
the Author came to do. From then on the button lists in one click.

The Name arrives from the provider the Author signed in with, and it is theirs
from that moment: a later sign in never writes over it. It is rewritten on the
list of their own Stories, which is the one page in the product that is about
them rather than about a Story, and the session carries it so every surface
showing it — the Catalogue, their Profile, that header — shows what was last
written.

## Consequences

**Publishing goes on asking for nothing.** A public link is handed to people the
Author chose; nobody browses to it and nothing signs it. The Name is required to
be found and never to be read.

**A Name cannot be unwritten.** Blank is refused rather than stored, because
nothing appears under a Name nobody wrote: erasing one would be a way out of the
Catalogue through a field that is not about the Catalogue. An Author who wants a
Story off the shelf unlists it.

**The email is on no screen.** It is what an Author is keyed on, and the header
that used to show it now shows the Name — the query behind a Profile does not
even select it.
